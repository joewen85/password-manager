# iPhone Duo 原生适配验证

验证日期：2026-10-10。范围仅为 iOS 原生端的布局、导航、系统工具栏及尺寸变化时的草稿保持；密码库格式、加密、认证、同步和导入导出协议沿用现有实现。

## 环境与实现

- Xcode 27.1，iOS 27.1 SDK，最低部署版本 iOS 17，支持 iPhone / iPad。
- 使用系统 `NavigationSplitView`、`NavigationStack`、`Form`、`List`、`ScrollView`、sheet 和 toolbar，按当前可用空间呈现导航及操作。
- 未添加按设备型号、屏幕尺寸或折叠角度分支；当前布局无需额外的 reserved-region 或铰链 API。
- 编辑弹窗通过独立呈现对象绑定条目，编辑和设置草稿在同一次呈现中只初始化一次。
- 大字体下列表图标占位随正文尺寸缩放，避免图标与标题重叠。
- 初始化/解锁主按钮位于底部安全区域，横屏键盘弹出后仍可操作。

## 测试隔离

Debug 模拟器以 `--ui-testing-vault` 启动时，为每次启动创建独立临时加密密码库，包含无真实凭据的 Alpha / Beta 条目。它通过正常初始化流程建立密码库，不访问用户密码库或同步设置。该入口仅编译进 Debug simulator，Release 和真机不包含它。

首屏与键盘测试仅检查初始化/解锁界面，不提交测试输入。发布安装 smoke 会卸载指定设备上的应用，因此必须使用临时模拟器，不能指向准备好的 Duo。

```sh
swift test
xcodebuild test -project PasswordManageriOS.xcodeproj \
  -scheme PasswordManageriOS -configuration Debug \
  -destination 'id=<测试模拟器 UDID>' \
  -derivedDataPath /tmp/password-manager-ui-tests \
```

## 后续键盘与分类快捷项修复（2026-10-10）

Computer Use 复现：分类输入框出现光标但没有软键盘；调整 Device Hub 的 Device → Keyboard 硬件/软件键盘设置后，重新打开分类并点击输入框可自动显示软键盘。应用没有加入强制显示键盘逻辑。

另一个独立问题是点击说明文字后仍保持编辑状态，键盘不收起。新增 UI 回归在修复前明确失败于“点击非输入内容必须结束编辑”。修复通过当前 scene 的窗口监听非输入区域点击并结束编辑；输入框、文本编辑器及其内部选择操作不触发收起，也不取消按钮触摸。分类快捷项、编辑页导航栏及解锁页说明文字均纳入键盘回归。

服务器、服务、账号三个快捷项保留原有字段并追加“用户名”“密码”，沿用现有去重和模板保存流程；独立分类与条目编辑内的分类创建共用此预设。新增参数化测试覆盖三种预设的凭据字段、去重及锁定后重新解锁的持久化，更新分类与快照字段断言。修复前预设测试因缺字段失败，修复后 Core 全部 128 项通过。

Computer Use 已在独立临时密码库中观察到服务器、服务、账号三个快捷项的用户名、密码；点击分类输入区域自动弹出软键盘，点击说明文字或服务快捷项后键盘收起，再次聚焦可重新弹出。手动分类草稿均取消，未保存测试分类。准备好的 Duo 保留，未卸载或清除其密码库。

最终验证：Core 全部 128 项通过；Duo 全量 9 项中 8 项通过，编辑测试因点击不可见的表单标题失败，改为点击可见导航栏后单项复测通过；普通 iPhone 17 的分类、编辑、搜索导航、密码页键盘与旋转 4 项全部通过；Release 模拟器构建通过。分类回归同时检查输入间切换继续编辑、取消不保存，编辑回归检查键盘收起后草稿仍保留。真机尚未验证。

## 展开竖屏底部功能栏（2026-10-12）

在 phone、regular 宽度且当前可用区域高于宽的布局中，将功能栏作为内容上方的底部居中浮层。iOS 26 及以上使用系统 `glassEffect(.regular, in: Capsule())`；较低版本使用 material。采用 26 pt 图标、简短文字及 56 pt 高操作区域，胶囊最大宽度 560 pt、高度 76 pt。普通窄屏 iPhone、iPad 和内屏横向继续使用系统工具栏。新增、导入、锁定始终可用，选择条目后增加导出、编辑、删除，避免重复操作入口。

Computer Use 操作 Xcode Device Hub 的 iPhone Duo（iOS 27.1），切换 Open 并旋转内屏，验证底部玻璃栏居中、大图标与文字可见、编辑弹窗打开及取消。初次实现复现底部搜索栏与功能栏重叠；最终使用覆盖内容的浮层，竖屏搜索框固定在列表顶部，并为底部滚动内容保留安全空间。列表背景延伸到胶囊下方，没有独占底栏。横屏恢复原生侧边操作栏。全部使用独立临时测试密码库，未卸载或清除准备好的 Duo。

Core 回归共 138 项通过（133 项 Swift Testing、5 项 XCTest）。布局测试覆盖展开竖屏、横屏、紧凑宽度、iPad 和正方形窗口。Duo 专项 UI 按实际 window frame 判断内屏方向，覆盖底部位置、居中、搜索栏避让、操作唯一及编辑取消；真实竖屏与横屏均单独通过。Device Hub 的内屏方向与 XCTest orientation 枚举不总是一致，因此不以枚举值代替实际窗口尺寸。

UI 测试通过启动参数固定应用语言，兼容系统侧栏按钮的中文标签。最终 Duo 全量回归执行 11 项，10 项通过、1 项 iPad 专属测试跳过、0 失败，包含设置草稿保持与关闭不保存。此前一次全量运行中，首屏测试遇到模拟器 `kAXErrorServerNotFound`；该用例单独复跑通过，随后全量重跑也全部通过。新版浮层专项检查胶囊尺寸、按钮高度、列表延伸到浮层下方、搜索避让及编辑取消。真机的玻璃观感及较低 iOS 版本的 material 回退尚未手动验证。

详情页顶部栏调整（2026-10-12）：展开竖屏时保留系统返回键，将玻璃标题与图标功能栏放在其右侧同一行。使用 Device Hub 的 iPhone Duo（iOS 27.1）打开独立测试库中的条目，确认返回键、标题、4 个快捷操作和更多菜单同排；打开更多菜单后点击系统返回键，列表成功恢复。窄标题会按剩余宽度截断。此次未运行 XCTest；Swift Testing 139 项通过，iOS 27.1 模拟器构建通过。
